# ภาพรวมระบบและ Workflow ปัจจุบัน

> ตรวจทานล่าสุด: 29 ตุลาคม 2569

เอกสารนี้เป็นภาพรวมสถานะปัจจุบันของ Valor ERP สำหรับผู้ดูแลระบบและผู้พัฒนาต่อ หากรายละเอียดในเอกสารเก่าขัดกับไฟล์นี้ ให้ตรวจยืนยันกับ `backend/routes/api.php`, `RoleAccess.php`, migration และโค้ดบริการที่ใช้งานจริงก่อนเสมอ

## บทบาทและขอบเขตหลัก

| บทบาท | งานหลัก |
|---|---|
| Sale | สร้าง/แก้ Draft ใบเสนอราคาและบิล, ส่งอนุมัติ, ยืนยันการซื้อขาย, แนบ PO/ใบเสนอราคาที่ลูกค้าเซ็น, Call Sale, ตารางงาน, เครดิต และจอง FibroScan |
| Approve | ตรวจและอนุมัติ/ตีกลับ/ไม่อนุมัติรายการ, ดูรายงาน Call Sale, Dashboard, เอกสาร และพิจารณาการจอง FibroScan |
| Admin / Sale COO | จัดการระบบส่วนกลาง, Master Data, เครดิต, ผู้ใช้, เอกสาร, คิวจัดเตรียมเอกสาร, Export Bplus/PDF/PO และเครื่อง FibroScan |
| Super Admin | เข้าถึงเมนูรวมและ Audit Log พร้อมจัดการสิทธิ์รายผู้ใช้ |

Admin สามารถเปิดหรือปิด ability รายผู้ใช้เพิ่มเติมจากสิทธิ์ตั้งต้นของ Role ได้ การตรวจสิทธิ์ต้องทำทั้ง Frontend route guard และ Backend middleware

## Workflow ใบเสนอราคาและเปิดบิล

1. Sale เลือกเส้นทางสร้างใบเสนอราคา หรือเปิดบิลจาก PO โดยตรง
2. ระบบดึงลูกค้า ที่อยู่ออกบิล ที่อยู่จัดส่ง เครดิต สินค้า และหน่วยจาก Master Data
3. Sale เลือก VAT แบบ In VAT หรือ Ex VAT และเลือก Template ใบเสนอราคา
4. Sale แก้ Draft ใน Quotation Document Editor ระบบ Autosave และ Preview PDF จากข้อมูลชุดเดียวกัน
5. Sale ส่งอนุมัติ Approve ตรวจ Revision ล่าสุดและบันทึกผลอนุมัติ/ตีกลับ/ไม่อนุมัติ
6. หลังอนุมัติ Sale ยืนยันการซื้อขายด้วยช่องทางที่ระบบรองรับ เช่น Customer Portal, ใบเสนอราคาที่ลูกค้าเซ็น หรือ PO ลูกค้า; กรณี PO ต้องบันทึกเลข PO และเก็บไฟล์ต้นฉบับ
7. ถ้าต้องจัดเตรียมเอกสาร Sale เลือก Checklist เอกสาร ส่วน Sale COO/Admin จัดทำและแนบไฟล์ในคิวเอกสาร Sale ดาวน์โหลดเมื่อสถานะพร้อม
8. Admin ตรวจรายการพร้อมส่งออก แล้ว Export Excel Bplus, PDF ใบเสนอราคา หรือชุด PO และปิดงาน

Template โรงพยาบาลเก็บรูปแบบภาษาตามข้อกำหนดของโรงพยาบาล การเปลี่ยนภาษาหน้าเว็บไม่ควรเปลี่ยนข้อความบังคับใน Template นั้น ส่วน Template มาตรฐานรองรับการเลือกข้อมูลที่อยู่และการปรับองค์ประกอบเอกสารตามสิทธิ์

## Master Data

- ลูกค้าและที่อยู่: ลูกค้าหนึ่งรายมีหลายที่อยู่ แยกประเภทออกบิล/จัดส่งและตั้งค่าเริ่มต้นได้
- สินค้า: เก็บรหัส ชื่อ รายละเอียด และข้อมูลราคา
- หน่วยสินค้า: หน่วยส่วนกลางใช้ได้กับสินค้าทุกชิ้น ค่าเริ่มต้นคือ `ชิ้น`; หากไม่มีหน่วยที่ต้องการ Sale ติดต่อ Admin ให้เพิ่ม
- พนักงานขาย: เก็บรหัสพนักงานขายสำหรับ Export Bplus และผูกกับบัญชีผู้ใช้
- เครดิต: เก็บวงเงิน เครดิตเทอม และยอดคงค้างตามข้อมูลล่าสุดที่ Import/ปรับปรุง

## Call Sale Report

รองรับการกรอกผ่านหน้าเว็บและ Import Excel ทั้งแบบหนึ่งชีตต่อวันและหนึ่งชีตรวมช่วงเวลา ระบบรองรับหัวคอลัมน์ภาษาอังกฤษ Status ไม่บังคับแต่มีผลต่อความแม่นยำของ Working Day ส่วน Date ต้องมาจากคอลัมน์หรือชื่อชีตที่ระบบอ่านได้ รายละเอียดและสูตรอยู่ใน `docs/CALL_SALE_REPORT.md`

## การจองเครื่อง FibroScan

Admin จัดการเพิ่ม แก้ไข เปลี่ยนสถานะ และลบเครื่องที่ไม่มีข้อมูลอ้างอิงได้ ผู้ใช้ที่มีสิทธิ์ส่งคำขอจอง ระบบตรวจช่วงเวลาซ้อนเฉพาะรายการที่อนุมัติและยังใช้งานอยู่ Approve/Admin พิจารณาคำขอ และผู้มีสิทธิ์ปรับสถานะจองแล้ว กำลังใช้งาน คืนแล้ว หรือยกเลิก

## เอกสารและหลักฐาน

- PDF Revision เก็บ Snapshot และ SHA-256 เพื่ออ้างอิงเอกสาร ณ เวลานั้น
- PO และเอกสารลูกค้าเก็บแบบ Version ไม่เขียนทับประวัติเดิม
- การดาวน์โหลดผ่าน API บันทึก Audit Log พร้อมชนิดเอกสาร เลขอ้างอิง ชื่อไฟล์ และ SHA-256 เมื่อมี
- หนังสือมอบอำนาจเห็นและจัดการโดย Document Preparation/Admin ตามสิทธิ์ ไม่แสดงเป็นเอกสารทำงานหลักของ Sale

## การตั้งค่าและภาษา

การตั้งค่าผู้ใช้ครอบคลุมภาษา รูปแบบตัวเลข/วันเวลา ข้อมูลโปรไฟล์ โทรศัพท์ รหัสผ่าน ลายเซ็น และการแจ้งเตือน การแปลต้องใช้ resource กลางและมี fallback ไม่ควรเขียนข้อความใหม่แบบตายตัวใน Component ภาษาเดียว

## การดูแล Production

- Deploy จาก private Git repository ผ่าน Docker/Render
- Database และ Storage อยู่บน Supabase
- Secret อยู่ใน Environment ของ Backend/Render เท่านั้น
- รัน migration ตามลำดับและกำหนด GRANT สำหรับตารางใหม่
- สำรองข้อมูลวันละ 2 รอบ แยกเก็บภายในบริษัทและ Cloud
- ตรวจ Health, Login, Workflow สำคัญ, PDF/Excel/PO และ Restore ตามรอบที่กำหนด
