# ประวัติการดาวน์โหลดเอกสาร

ใช้ตาราง `audit_logs` เดิม ไม่ต้องรัน schema เพิ่ม ดูที่หน้าบันทึกกิจกรรมระบบ เลือกหมวด “เอกสาร” และกด “ดูข้อมูล” ค้นหาเลขใบเสนอราคาได้ รวมถึงเลขที่อยู่ในรายการส่งออกรวม

ข้อมูลใหม่อยู่ใน `request_data.document_download`: ประเภทเอกสาร, quotation_id, quotation_no (เมื่อมี), bill_id, revision_no, ชื่อไฟล์ใน Content-Disposition และ SHA-256 ของไฟล์ตอบกลับ สำหรับไฟล์แนบมี document_id และ file_version เพิ่ม ส่วน PDF รวมและ Excel มีรายการเอกสารใน documents

Revision ของไฟล์แนบหมายถึง Revision ปัจจุบันของบิลขณะดาวน์โหลด ไม่ใช่การยืนยันว่าไฟล์แนบนั้นถูกลงนามใน Revision ดังกล่าว ให้ใช้ file_version และ SHA-256 อ้างอิงไฟล์แนบจริง

ทุกคำขอดาวน์โหลดซ้ำผ่าน API บันทึกแยกเป็นกิจกรรม โดยไม่สร้างเลขใบหรือ Revision ใหม่ ไม่เพิ่มหลักฐานดาวน์โหลดสำเร็จให้คำขอที่ล้มเหลวหรือ HEAD ระบบบันทึกเมื่อสร้าง response สำเร็จ ไม่สามารถยืนยันการรับไฟล์หรือการพิมพ์กระดาษ และไม่สามารถติดตามการพิมพ์ไฟล์ที่ผู้ใช้เก็บไว้ในเครื่องได้

ครอบคลุมใบเสนอราคาต้นฉบับ/สำเนา/ชื่อที่แก้ไข, PDF รวม, Excel Bplus, เอกสารบิล, ใบรับรองอนุมัติ, PO, ใบที่ลูกค้าเซ็น และดาวน์โหลดผ่าน Customer Portal โดยผู้ใช้ Portal ระบุเป็น Customer Portal ไม่ถือเป็นการพิสูจน์ตัวบุคคล

ข้อมูลย้อนหลังเดิมยังคงอยู่ แต่ไม่สามารถเติม Revision และแฮชไฟล์ย้อนหลังอย่างแน่นอนได้ ระบบใช้ event action เดิมเพื่อให้ตัวกรองและข้อมูลเก่ายังทำงานร่วมกันได้ ข้อมูลนี้ใช้สิทธิ์อ่าน audit_logs เดิม ไม่มีการขยายสิทธิ์ให้ Sale

จุดแก้ไข: DocumentDownloadAudit.php เก็บข้อมูลเอกสารจาก controller และ AuditLogger.php เติมข้อมูลลง Log หลังสร้าง response โดยไม่เชื่อข้อมูล document_download จากผู้เรียก API ส่วน DocumentCenterView.vue รวมปุ่มดาวน์โหลดในเมนูเดียวต่อแถว
